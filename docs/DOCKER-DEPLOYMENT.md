# Docker deployment

This setup runs the React frontend and Express API in one application container, with MySQL in a separate container. Only the application port is published. The database uses a persistent Docker volume.

## 1. Configure

For Dokploy, use the [Dokploy guide](DOKPLOY.md) and `compose.dokploy.yaml` instead of the local Compose instructions below.

Install Docker with Docker Compose support (Docker Desktop using Linux containers on Windows). From the project root, create `.env.docker` with:

```dotenv
APP_PORT=8080
MYSQL_PASSWORD=YOUR_RANDOM_HEX_APP_PASSWORD
MYSQL_ROOT_PASSWORD=YOUR_DIFFERENT_RANDOM_HEX_ROOT_PASSWORD
JWT_SECRET=YOUR_DIFFERENT_RANDOM_HEX_JWT_SECRET
```

Replace each placeholder with a separate value generated by:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Use hexadecimal database passwords as shown, because the application password is embedded in a database URL. `.env.docker` and other local environment files are excluded from Git and the Docker build context.

## 2. Build and start

```powershell
docker compose --env-file .env.docker up -d --build
docker compose --env-file .env.docker ps
```

Open **http://localhost:8080** (or the port configured in `APP_PORT`). Docker initializes the schema only when the database volume is empty. Existing Laragon/MySQL data is not copied automatically.

## 3. Create the administrator

In PowerShell, enter the password without writing it in the command history:

```powershell
$adminCredential = Get-Credential -UserName admin -Message "Choose the initial administrator password (at least 8 characters)"
$env:ADMIN_USERNAME = $adminCredential.UserName
$env:ADMIN_PASSWORD = $adminCredential.GetNetworkCredential().Password
try {
  docker compose --env-file .env.docker exec -e ADMIN_USERNAME -e ADMIN_PASSWORD app node server/dist/scripts/create-admin.js
} finally {
  Remove-Item Env:ADMIN_USERNAME, Env:ADMIN_PASSWORD
}
```

Sign in with that account. Running this command for an existing username resets its password and makes it a super administrator.

## Operations

```powershell
# View logs
docker compose --env-file .env.docker logs -f app

# Stop containers while preserving database data
docker compose --env-file .env.docker down

# Rebuild after source changes
docker compose --env-file .env.docker up -d --build
```

Do not use `down -v` unless you intend to delete the database volume. Changing environment passwords does not change credentials in an already initialized MySQL volume. Keep backups before database maintenance.

For an internet-facing deployment, place the application behind an HTTPS reverse proxy. The Compose setup itself provides HTTP. The image runs as the non-root Node user, and its health check checks API availability; Compose checks the database schema before starting the app.

## Build the application image only

```powershell
docker build -t collection-monitoring .
```

For an externally managed MySQL database, supply `DATABASE_URL` and `JWT_SECRET` when running this image, and initialize that database with `database/schema.mysql.sql` first. No credentials or administrator account are built into the image.
